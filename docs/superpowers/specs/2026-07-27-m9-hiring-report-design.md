## Objective

Extend the Phase 1 basic report with a fully compiled, explainable hiring document. Every score is traceable to a quoted answer excerpt. The full report generates within 5 minutes of session submission. Low AI Confidence Score routes to mandatory human review.

Pipeline order per §11.3:

```
Evaluation → Exec Summary → Behavior Inference → Integrity Checks
           → Recommendation Agent → Report Generator Agent
```

## Recommendation Agent

### Entry point

```python
# agents/recommendation/agent.py
def synthesize_recommendation(
    session_id: uuid.UUID,
    db_factory: Callable[[], Session],
) -> None:
```

Opens its own DB session. On any exception: logs, returns — pipeline continues (non-fatal, same pattern as `_run_behavior_inference`).

### Inputs (all from DB)

| Source | Fields used |
|--------|-------------|
| `hiring_reports.score_rollup` | `competency_scores`, `composite_scores`, `overall`, `answered_count`, `question_count` |
| `behavior_profiles` | `disc_style`, `big_five`, `leadership_style`, `decision_style`, `communication_style`, `work_style`, `stress_signal`, `eq_signal` |
| `hiring_reports.integrity_summary` | `overall_risk`, `flagged_count` |
| `job_assessments` | `title`, `difficulty_level`, `role_family`, `required_skills`, `experience_min`, `experience_max` |
| `candidates` | `name` |

### AI Confidence Score computation (§9.4)

Computed deterministically before the LLM call; passed into the prompt as context so the LLM can explain it — the LLM does not recalculate it.

```
coverage     = answered_count / question_count          (0.0–1.0)
consistency  = max(0, 1 − std_dev(competency_scores) / 4)
integrity    = {"low": 1.0, "medium": 0.6, "high": 0.3}[overall_risk]
behavior     = 1.0 if behavior_profile exists else 0.7

confidence   = round(
    (coverage * 0.40 + consistency * 0.30 + integrity * 0.20 + behavior * 0.10) * 100,
    1
)
```

If `confidence < 60` → `requires_human_review = True` (written into `full_report["meta"]`). §9.4/§15 requirement.

### LLM call

One forced tool call to `claude-sonnet-4-6`, tool `synthesize_recommendation`.

**Tool output schema:**

```json
{
  "verdict_reasoning": "3–4 sentences citing specific scores and evidence",
  "salary_band": "band label e.g. 'L3 / Mid-Senior' — never a figure",
  "salary_band_rationale": "string",
  "training_needs": [
    {"area": "string", "priority": "high|medium|low"}
  ],
  "suggested_ceo_questions": ["string", "string", "string"]
}
```

`ai_confidence_score` and `requires_human_review` are computed before the call and not in the tool schema — they are deterministic.

### Writes to `hiring_reports`

`salary_band`, `ai_confidence_score`, `suggested_ceo_questions`. `training_needs` on the DB column (ARRAY(Text)) is written as flattened strings (`"{area} ({priority})"`); the rich `[{"area":..,"priority":..}]` form lives only in `full_report` JSONB (written by Report Generator).

Salary band note (§18 Open Question #1): the band label is a role-level descriptor (`L3/L4 Senior Engineer`). Org-specific comp bands (rupee ranges) are out of scope at MVP — `salary_band` stores the label only.

## Report Generator Agent

### Entry point

```python
# agents/report_generator/agent.py
def generate_full_report(
    session_id: uuid.UUID,
    db_factory: Callable[[], Session],
) -> None:
```

Non-fatal, same pattern.

### Two-stage LLM calls

Both calls use `claude-sonnet-4-6`, max_tokens=4096 each.

**Call 1 — Narrative tool** (`generate_report_narrative`)

Input assembled from DB: candidate name, job title, composite scores, competency scores, behavior profile, integrity summary, verdict + reasoning (from Recommendation Agent), resume summary from `candidate_profiles.summary`, answer excerpts from `session_questions.evaluation[].explanation` fields.

Produces prose for all narrative sections. Each strength and weakness **must** cite a quoted answer excerpt (§3 explainability goal); system prompt enforces this.

Narrative sections:
- `executive_summary` — 2–3 sentences, verdict with reasoning
- `candidate_overview`
- `resume_summary`
- `interview_summary`
- `culture_fit`
- `domain_knowledge`
- `skill_gap_analysis`
- `strengths` — array, each item cites answer excerpt
- `weaknesses` — array, each item cites answer excerpt
- `potential_risks`
- `learning_curve_estimate`
- `management_readiness`
- `promotion_potential`
- `integrity_summary_prose` — human-readable rendering of M8 flags (severity + evidence); human makes the call, never automatic reject
- `final_verdict` — full paragraph, never a bare label

**Call 2 — Structured tool** (`generate_report_structured`)

Input: narrative output for context + all score data + benchmarks.

Produces:
- `scores` — per-composite with `score`, `vs_job_bar`, `vs_org_bar`
- `overall_rating` — numeric
- `recommended_next_round`
- `training_needs` — confirmed or refined from Recommendation Agent output
- `suggested_hr_questions` — 3 items
- `suggested_ceo_questions` — 3 items (sourced from Recommendation Agent, confirmed here)

### Benchmarking (M9-F03)

**Job bar:** derived from `VERDICT_BANDS` in `agents/scoring/rubric.py`. Score ≥ 3.50 = "meets bar"; 2.75–3.49 = "borderline"; < 2.75 = "below bar". `vs_job_bar` is the numeric delta from the 3.50 "hire" threshold.

**Org historical bar:** query `hiring_reports` joined to `assessment_sessions` → `job_assessments` where `role_family` matches and `verdict IN ('hire', 'strong_hire')`, return median `score_rollup->>'overall'`. If fewer than 3 matching records: `vs_org_bar = "insufficient_data"`.

## API Endpoints

### New endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/reports/{session_id}/full` | recruiter/admin JWT | Full M9-F02 report |
| `GET` | `/reports/{session_id}/pdf` | recruiter/admin JWT | PDF download |
| `POST` | `/reports/{session_id}/share` | recruiter/admin JWT | Create expiring share link |
| `GET` | `/reports/shared/{token}` | public (token in path) | Client-scoped view |
| `PATCH` | `/reports/{session_id}/feedback` | recruiter/admin JWT | Reviewer decision + overrides |

### Existing endpoint (unchanged)

`GET /reports/{session_id}` — basic report, returns existing `ReportResponse`.

---

### GET `/reports/{session_id}/full`

Returns `FullReportResponse` — the `full_report` JSONB plus top-level fields (`verdict`, `ai_confidence_score`, `salary_band`, `requires_human_review`).

404 if report row missing or `full_report` is empty (`{}`).

---

### GET `/reports/{session_id}/pdf`

Calls `render_pdf()`. Query param `include_transcript=true` allowed only for recruiter/admin.

Streams response: `media_type="application/pdf"`.

---

### POST `/reports/{session_id}/share`

**Request:**
```json
{"client_id": "<uuid>", "expires_in_days": 7}
```

Creates `report_shares` row. Returns:
```json
{"share_token": "<uuid>", "expires_at": "<ISO timestamp>"}
```

`client_id` must belong to the same `org_id` as the report (validated via DB lookup).

---

### GET `/reports/shared/{token}`

- `token` is the `report_shares.id` UUID (not a JWT); looks up row by `id = token`
- 403 if `expires_at < now()` or `revoked_at` is set
- Returns scoped subset: no raw transcript, no integrity flag evidence detail (only `overall_risk` + `human_review_required`)
- No JWT required — share token acts as bearer

---

### PATCH `/reports/{session_id}/feedback`

**Request body (`ReviewerFeedbackRequest`):**
```json
{
  "final_decision": "hire | no_hire | hold",
  "comment": "string",
  "score_overrides": {"technical": 4.0}
}
```

**Writes:**
1. `hiring_reports.reviewer_override` — full payload + `submitted_at` timestamp + `discrepancy_flag` (true if `final_decision` contradicts AI `verdict`)
2. For each key in `score_overrides`: updates corresponding `composite_scores` entry in `hiring_reports.score_rollup` and writes a calibration-tagged entry (`"source": "recruiter_override"`) back to affected `session_questions.evaluation` (M6-F04)

Returns 200 with updated `reviewer_override`.

## Pipeline Wiring (`agents/evaluation/pipeline.py`)

Two new helper functions added after `_run_integrity_checks`:

```python
def _run_recommendation(db: Session, session_id: uuid.UUID) -> None:
    try:
        from agents.recommendation.agent import synthesize_recommendation
        synthesize_recommendation(session_id=session_id, db_factory=lambda: db)
    except Exception:
        logger.exception("recommendation synthesis failed for session %s", session_id)


def _run_report_generator(db: Session, session_id: uuid.UUID) -> None:
    try:
        from agents.report_generator.agent import generate_full_report
        generate_full_report(session_id=session_id, db_factory=lambda: db)
    except Exception:
        logger.exception("report generation failed for session %s", session_id)
```

Called at end of `evaluation_pipeline()`:
```python
_run_integrity_checks(db, session_id)
_run_recommendation(db, session_id)
_run_report_generator(db, session_id)
```

## Constraints

- §15: No biometric, emotion-based, or protected-characteristic signals in any prompt or score field
- §9.5: Verdict must always be accompanied by `verdict_reasoning` — bare label is never written
- §3 Explainability: every strength/weakness bullet must cite a quoted answer excerpt
- §18 Open Question #1: `salary_band` is a role-level descriptor, not a rupee figure; org comp bands are provided externally at MVP
- §18 Open Question #4: integrity recall/FP targets unverifiable until labeled validation set ships; `open_question` field remains in `integrity_summary`
- M8 constraint: `integrity_summary_prose` is advisory; report never triggers automatic reject
- Share link: Client-role view omits raw transcript and integrity flag evidence detail
- `report_shares` requires `client_id` scoped to the same org (validated on create)
